# 仓库文档同步指南

本文介绍如何准备代码仓库、配置 DocHub 项目，并让仓库中的文档正确同步、进入目录树和全文搜索。

适用于项目创建人、仓库维护者和协助排查同步问题的系统管理员。系统内的日常阅读与权限操作可参阅[《使用手册》](./1-user-guide.md)，管理员维护操作可参阅[《管理手册》](./3-admin-guide.md)。

## 1. 开始前需要准备什么

要让 DocHub 成功读取一个仓库，至少需要满足以下条件：

1. 仓库创建人或 GitLab Group 管理员已将通用同步用户 `Jenkinsadmin` 添加为仓库成员，并授予只读权限。
2. 仓库包含至少一个文档目录，目录中有 `.md`、`.html` 或 `.htm` 文件。
3. 需要展示的分支已明确配置，例如 `main`、`master` 或 `release/1.0`。

DocHub 使用服务器统一维护的 SSH 私钥访问仓库。项目成员自己的 Git 权限不参与服务器同步，仓库必须直接授权给与这把私钥绑定的通用用户 `Jenkinsadmin`。

如果仓库属于某个 GitLab Group，也可以将 `Jenkinsadmin` 加入该 Group，并授予能读取代码的只读角色。仅能看到仓库页面但无法读取代码，仍然不能完成同步。

## 2. 推荐的仓库目录结构

将需要发布的文档集中放在独立目录中，例如：

```text
my-service/
├── docs/
│   ├── README.md
│   ├── getting-started.md
│   ├── api/
│   │   ├── overview.md
│   │   └── reference.html
│   ├── images/
│   │   └── architecture.png
│   └── styles/
│       └── reference.css
└── src/
    └── ...
```

接入项目时将“文档目录”填写为 `docs`。DocHub 只会从配置的文档目录建立文档快照，`src` 等其他目录不会出现在文档站点中。

需要从多个目录读取文档时，可以配置多个文档根目录，例如：

```text
docs
design
api-guide
```

每个项目最多配置 10 个文档根目录。目录不能重复，也不能配置成包含关系，例如不能同时配置 `docs` 和 `docs/api`。

嵌套目录可以直接使用，不需要在 DocHub 中逐级创建：

```text
docs/
├── backend-sdk/
│   ├── task-api.md
│   └── callback.md
└── database/
    └── index-design.md
```

同步后会显示为 `docs > backend-sdk > task-api.md` 等层级。

## 3. 支持的文件类型

| 文件类型 | 系统行为 |
| --- | --- |
| `.md` | 在 DocHub 阅读页渲染，支持标题、表格、代码块、Mermaid、相对图片和内部文档链接 |
| `.html`、`.htm` | 在隔离 iframe 中渲染，支持 HTML、CSS、JavaScript 和本地相对资源 |
| 图片、CSS、字体和脚本等 | 作为文档资源保留，并在被文档引用时加载 |

文件扩展名不区分大小写。单个 `.md`、`.html` 或 `.htm` 文件不能超过 5 MiB，超过限制的文件不会进入文档索引。

符号链接会被跳过。请将正式文档保存为普通文件，不要依赖指向文档目录外部的符号链接。

空目录不会单独显示，因为系统目录树是根据实际文档路径生成的。

配置的文档目录会在同步时整体复制到快照中。不要把密码、Token、私钥或其他敏感文件放在文档目录里。

## 4. 文档标题和搜索内容

DocHub 会为每篇文档自动建立标题和可检索文本：

- Markdown 默认使用第一个一级标题作为文档标题；没有一级标题时使用文件名。
- HTML 默认使用 `<title>` 作为文档标题；没有 `<title>` 时使用第一个 `<h1>` 或文件名。
- 全文搜索范围包括文档标题、仓库内完整路径和正文文本。
- HTML 正文中的可见文字会进入全文搜索；`script`、`style` 等不可见内容不会作为正文入库。

建议在每个文档根目录提供 `README.md` 或 `index.html`。进入项目时，系统会优先打开这些入口文档。

## 5. 接入仓库

在 DocHub 项目列表点击“接入项目”，填写以下信息：

### 5.1 项目名称和描述

项目名称用于项目列表和文档页展示。项目描述可以简要说明仓库用途，最多 500 个字符，并会显示在项目列表中。

### 5.2 SSH 仓库地址

当前只支持 SSH 形式的 Git 地址，例如：

```text
git@git.example.com:team/project.git
ssh://git@gitlab.example.com:2222/team/project.git
```

不支持填写 `https://` 地址。地址中的主机必须已经配置在服务器的 `GIT_HOST_ALLOWLIST` 中。

### 5.3 可见范围

- **私有**：只有项目创建人、系统管理员和获得项目或文档授权的用户可读。
- **公开**：所有已登录的 DocHub 成员可读，但不开放给未登录访客。

### 5.4 文档目录和分支

文档目录填写仓库内的相对路径，例如 `docs`、`design`。不要填写服务器本地路径，也不要添加开头的 `/`。

跟踪分支填写希望提供阅读版本的分支名称。每个分支拥有独立快照，因此 `main` 和 `release/1.0` 可以同时展示不同版本的文档。

点击“创建并同步”后，系统会异步拉取仓库并生成首批文档快照。

## 6. 什么时候会重新同步

目前文档更新不会在每次 Git push 后自动生效。以下操作会触发同步：

- 创建项目后首次同步。
- 点击文档页面的“同步”按钮。
- 修改项目的仓库地址或文档目录。
- 添加新的跟踪分支。

将文档推送到仓库后，记得进入对应分支并手动点击“同步”。同步只更新当前选中的分支；其他分支需要分别同步。

同步失败时，系统会保留上一份成功快照。页面会继续展示旧版本，同时显示失败状态和简化后的错误提示。

## 7. 同步后的显示效果

项目同步成功后：

- 左侧目录会按仓库结构展示 Markdown 和 HTML 文档。
- 可以在“文档目录”右侧切换目录树和扁平文件列表，默认使用目录树。
- 搜索会匹配当前分支中的标题、路径和正文，并高亮命中的关键词。
- 页面可以按已配置的分支切换不同文档快照。
- 文档页支持下载原文；项目管理员可以配置项目级和文档级读取权限。

Markdown 文档之间的相对链接会尽量转换为 DocHub 内部文档跳转。指向图片、PDF 或其他非文档资源的相对链接会作为资源打开。

## 8. Markdown 资源和链接

推荐使用相对于当前文档的路径：

```markdown
![架构图](./images/architecture.png)

[接口说明](./api/overview.md)

[下载完整示例](../files/example.zip)
```

图片、附件和 CSS 等资源应放在配置的文档目录中，并通过相对路径引用。

文档资源路径不能使用 `../` 跳出文档快照范围。仓库代码或服务器文件不能通过 Markdown 资源链接访问。

## 9. HTML 文档和沙箱限制

HTML 文档在禁止同源访问的 sandbox iframe 中运行。HTML 可以使用内联脚本、内联样式和相对资源，但运行代码不能访问 DocHub 登录信息、父页面、浏览器本地存储中的 DocHub 数据或顶层窗口。

为了正常加载本地资源，请在 HTML 中使用相对路径：

```html
<link rel="stylesheet" href="./styles/reference.css">
<img src="./images/architecture.png" alt="架构图">
```

HTML 及 CSS 中通过 `@import`、`url()` 引用的本地资源会同步建立权限关系。请避免使用以 `/` 开头的站点根路径，例如 `/assets/app.css`，这类路径无法映射到仓库文档目录。

当前安全策略会阻止以下 HTML 能力：

- 提交表单。
- 嵌入 `<object>`。
- 嵌套 iframe。
- 使用 meta refresh 自动跳转。
- 访问或修改 DocHub 父页面。

外部 HTTPS 脚本、样式和图片可以加载。只同步受信任仓库的文档，不要在 HTML 中引入不可信的第三方脚本。

## 10. 私有仓库权限检查

出现“无法访问代码仓库”时，优先检查通用同步用户 `Jenkinsadmin`：

1. GitLab 中能搜索到 `Jenkinsadmin` 用户。
2. `Jenkinsadmin` 已加入目标仓库或所属 GitLab Group。
3. 角色至少具备读取代码的权限，例如 Reporter。
4. 如果刚调整权限，回到 DocHub 点击“同步”重试。

只有仓库页面访问权限、开发分支权限或项目成员身份并不一定足够。同步账号必须能读取仓库对象和需要同步的分支。

## 11. 常见问题

### 克隆仓库失败

检查：

- `Jenkinsadmin` 是否拥有仓库或所属 Group 的只读权限。
- 仓库地址是否为 SSH 地址，是否包含错误的主机、端口或路径。
- Git 主机是否在 `GIT_HOST_ALLOWLIST` 中。
- DocHub 服务器的 SSH 私钥和 `known_hosts` 是否正确。
- 服务器能否访问 Git 主机。

### 提示分支不存在

确认分支已经推送到远端，并且分支名称大小写、层级和拼写正确。只存在于本地但尚未 push 的分支无法同步。

### 提示文档目录不存在

确认“文档目录”填写的是仓库中的相对路径，并且该目录存在于当前分支。不同分支可以有不同目录结构；目录只在部分分支存在时，这些分支可能同步失败。

### 同步成功但没有文档

检查：

- 文件扩展名是否为 `.md`、`.html` 或 `.htm`。
- 文件是否位于已配置的文档目录内。
- 单个文档是否超过 5 MiB。
- 文件是否是符号链接。
- 目录是否确实包含文件，而不是只有空子目录。

### 推送后页面还是旧内容

当前需要手动同步。确认切到了正确分支，然后点击“同步”。同步成功后重新打开文档或等待页面自动刷新。

### HTML 样式或图片缺失

检查资源是否位于文档目录内，并通过 `./` 或 `../` 相对路径引用。以 `/` 开头的站点根路径目前不可用。

### HTML 中的交互功能不可用

表单、嵌套 iframe、对象嵌入和自动跳转会被安全策略阻止。需要交互的页面应自行实现不依赖这些能力的 UI。

## 12. 接入检查清单

接入前：

- [ ] 仓库可通过 SSH 访问。
- [ ] `Jenkinsadmin` 已获得仓库或 Group 的只读权限。
- [ ] 文档位于独立的相对目录中。
- [ ] 文档扩展名为 `.md`、`.html` 或 `.htm`。
- [ ] 文档中的图片和附件使用相对路径。
- [ ] 已准备 `README.md`、`index.md` 或 `index.html` 作为入口。
- [ ] 确认需要展示的分支名称。

同步后：

- [ ] 项目状态显示“已就绪”。
- [ ] 左侧目录和搜索结果包含预期文档。
- [ ] 图片、CSS 和跨文档链接可以正常打开。
- [ ] HTML 文档在沙箱中正常渲染。
- [ ] 必要时已配置项目级或文档级读取权限。
