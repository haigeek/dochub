# DocHub {{PERSON_vw3nkssd}}手册

本手册面向 DocHub 系统管理员，说明用户与角色、组织机构、项目授权治理、单点登录和日常维护操作。普通成员的项目接入、文档阅读及个人账号操作请参阅[《使用手册》](./user-guide.md)。

## 1. 管理员职责

系统管理员负责维护 DocHub 的账号体系、组织结构和登录配置，并拥有全部项目的完整读取及管理权限。

主要职责包括：

- 创建和维护本地账号，调整成员与管理员角色。
- 维护组织机构及组织成员。
- 维护单点登录站点。
- 在必要时处理项目可见范围、项目授权和文档授权问题。
- 协助成员排查因账号、组织归属或授权造成的访问问题。

组织成员、项目创建人和普通文档读者不应被授予系统管理员角色，除非确实需要全局维护权限。

## 2. 进入管理后台

管理员登录后，点击页头右上角的设置图标进入管理后台。

左侧菜单包括：

- 用户管理：账号、角色和所属组织维护。
- 组织机构：组织名称及成员关系。
- 系统设置：单点登录站点配置。

左侧菜单可以收起为图标栏，以便在窄屏下继续操作。

## 3. 用户管理

“用户管理”页面展示账号用户名、角色、所属组织、创建时间和当前角色操作。

### 3.1 创建本地账号

1. 在“创建本地账号”区域填写用户名。
2. 设置至少 8 位的初始密码。
3. 选择角色为“成员”或“管理员”。
4. 点击“创建用户”。

创建后，请通过安全渠道将用户名和初始密码交付用户，并提醒用户登录后尽快修改密码。

本地账号密码由 DocHub 维护。单点登录用户首次登录时由系统自动创建成员账号，不需要提前手工创建。

### 3.2 调整角色

用户列表提供以下角色操作：

- 将普通成员设为管理员。
- 将管理员设为普通成员。

限制：

- 当前登录管理员不能修改自己的角色。
- 系统必须至少保留一个管理员，不能将最后一名管理员降为成员。

管理员拥有全部项目的创建、配置、同步和授权管理能力，角色调整应谨慎执行。

### 3.3 设置用户所属组织

1. 在用户列表找到目标账号。
2. 点击“设置组织”。
3. 选择一个或多个组织机构。
4. 点击“保存归属”。

用户可同时加入多个组织。清空选择并保存后，用户将不再通过任何组织获得项目或文档权限，但个人直接授权仍然有效。

组织归属变化会立即影响用户的读取权限，不需要重新登录或重新创建 Agent 凭证。

## 4. 组织机构

“组织机构”页面用于维护 DocHub 的扁平组织结构。

### 4.1 创建组织

1. 点击“新建组织”。
2. 填写组织机构名称。
3. 选择初始成员。
4. 点击“保存”。

组织名称要求：

- 去除首尾空格后不能为空。
- 长度为 1–100 个字符。
- 名称按忽略大小写的方式保持唯一。

### 4.2 编辑组织

点击组织行中的“编辑”，可以：

- 修改组织名称。
- 增加或移除组织成员。

成员的增加或移除会立即改变相关用户通过组织获得的权限。

### 4.3 组织模型

DocHub 当前采用扁平组织模型：

- 组织之间没有上下级关系。
- 不存在从上级组织向下级组织自动继承的授权。
- 一个用户可以直接加入多个组织。
- 用户最终读取权限是个人直接授权和全部所属组织授权的并集。

### 4.4 删除组织

点击组织行中的“删除”并二次确认后，会同时删除：

- 组织机构本身。
- 该组织的全部成员关系。
- 该组织在项目级和文档级的全部读取授权。

用户个人直接授权以及其他组织的授权不受影响。

删除组织可能立即移除多名用户的项目访问权限，执行前应确认影响范围。当前不提供组织恢复入口。

## 5. 项目和文档授权治理

管理员可以管理所有项目，并在项目创建人无法处理权限问题时进行全局治理。

### 5.1 查看项目范围

管理员可以在项目列表中看到全部项目，不受私有或授权范围限制。

文档页中的目录、正文、搜索、下载和附件访问仍按管理员完整权限处理。

### 5.2 项目可见范围

项目可配置为：

- **公开**：所有已登录用户可以读取。
- **私有**：只有项目创建人、管理员和获得项目级或文档级授权的用户可读取。

公开范围仅覆盖 DocHub 已登录用户，未登录访客不能访问。

切换公开或私有不会清除已有授权，也不会触发仓库重新同步。切回私有后，原有用户和组织授权继续生效。

### 5.3 项目级读取授权

在“项目管理 > 项目级读取权限”中，可以同时选择用户和组织机构。

- 用户或组织命中项目级授权后，可读取项目全部已同步分支和全部文档。
- 用户个人授权和组织授权取并集。
- 项目创建人和管理员无需额外授权。
- 修改后需要点击“保存项目权限”。

### 5.4 文档级读取授权

打开文档后，点击“文档权限”进行单篇授权。

- 文档权限按仓库完整路径生效，跨全部分支。
- 可同时授权给用户和组织。
- 授权后允许读取正文、下载原文，以及读取正文实际引用的图片和附件。
- 未授权文档即便位于同一项目目录中，也不能读取。

项目级权限已经覆盖整个项目时，单独配置文档级权限不会缩小现有读取范围。

### 5.5 权限排查顺序

用户反馈无法访问文档时，建议依次确认：

1. 账号是否已成功登录。
2. 项目是否为公开项目。
3. 用户是否属于被授权组织。
4. 是否存在有效的项目级或个人授权。
5. 是否存在目标文档的文档级授权或组织文档授权。
6. 项目分支是否已经同步成功。
7. 请求的文档路径是否与仓库中的完整路径一致。

组织成员变化和授权修改会立即生效。Agent 凭证沿用创建者的实时权限，无需重新创建。

## 6. 项目管理维护

管理员拥有与项目创建人相同的项目管理能力。

### 6.1 修改仓库和文档目录

修改 SSH 仓库地址或文档目录会：

- 清除当前项目的本地文档快照。
- 自动重新同步所有已配置分支。

修改前应确认配置正确，避免因仓库地址错误导致项目暂时无文档可读。

### 6.2 管理分支

管理员可以添加或移除跟踪分支：

- 添加分支后，系统会立即创建同步任务。
- 移除分支只会删除 DocHub 本地快照，不影响远端仓库。
- 项目至少需要保留一个跟踪分支。

同步失败时，系统保留上一份成功快照。应检查分支名称、仓库访问权限和网络后重试。

### 6.3 删除项目

删除项目会清除 DocHub 中的项目记录、本地镜像和全部文档快照，不会删除远端仓库。

该操作不可恢复。删除前应确认是否存在仍在使用的文档授权、Agent 链接或团队入口。

## 7. 单点登录管理

“系统设置”页面用于维护一个或多个单点登录站点。

### 7.1 新增站点

1. 点击“新增站点”。
2. 填写显示名称和客户端 ID。
3. 填写客户端密钥。
4. 配置身份服务的端点基础地址及授权、Token、用户信息路径。
5. 核对系统显示的回调地址，并在身份服务端登记相同地址。
6. 按需配置门户地址、固定签发方、Scope、PKCE 和身份字段映射。
7. 启用站点并保存。

客户端密钥提交后不会在页面回显。编辑站点时留空表示保持现有密钥；如需替换，重新填写新密钥；也可以勾选清除当前密钥。

### 7.2 回调地址

每个站点都有独立回调地址，格式为：

```text
/api/auth/oauth2/<站点 ID>/callback
```

页面会按当前访问地址自动填充完整回调 URL，支持手动修改；点击“自动填充”可恢复默认值。
站点列表展示实际保存的完整回调地址，与编辑页保持一致。
新建站点保存后，占位路径中的 `pending` 会替换为实际站点 ID，请使用保存后的最终地址在身份服务端登记。

可以修改外部域名、协议、端口和路径。自定义路径需要由反向代理转发至该站点的标准回调接口，
并保持与登录发起时相同的浏览器会话可用。不能使用其他站点的标准回调路径，例如将 TAM 站点指向 Collie 的回调接口。
回调地址必须使用 HTTP(S)，不能包含用户凭据、查询串或 fragment。

### 7.3 身份字段映射

默认映射：

- 用户 ID：`sub`
- 用户名：`name`

用户 ID 必须稳定且唯一，用于绑定 DocHub 本地账号。用户名只用于展示，不能作为账号绑定键。

自定义字段支持使用点分路径读取嵌套数据，例如 `data.id`。

### 7.4 启用和停用

- 停用站点后，登录页不再显示该入口。
- 停用不会立即撤销用户已有的 DocHub 会话。
- 删除站点只影响新的单点登录，不会删除已有账号、会话或文档授权。

来源系统退出或来源账号停用不会自动触发 DocHub 单点退出。当前仍以本地会话有效期为准。

### 7.5 首次登录用户

单点登录用户首次认证时会自动创建 DocHub 成员账号：

- 默认角色为普通成员。
- 默认不属于任何组织。
- 默认没有项目或文档授权。

首次登录后，管理员需要按实际团队关系为用户设置组织，或为其项目单独授权。

## 8. 账号和安全建议

- 至少保留两名可用管理员，避免单账号无法登录后失去后台维护能力。
- 管理员应优先使用单点登录；需要本地应急入口时，应保持本地管理员密码可用并定期更新。
- 组织名称使用稳定、可识别的团队或部门名称。
- 优先按组织授权项目，减少逐用户维护。
- 文档级授权用于少量、精确的访问场景。
- 不通过聊天工具明文传递管理员密码或客户端密钥。
- 删除组织或项目前，先检查成员、授权和团队使用情况。
- Agent 凭证由各用户自行维护，泄露后应立即撤销。

## 9. 常见问题

### 9.1 单点登录按钮没有出现

检查：

- 站点是否已启用。
- 服务器连接的数据库是否包含该站点配置。
- 登录页的 `/api/auth/options` 请求是否成功，是否返回了该站点。
- 部署镜像和浏览器加载的页面是否为当前版本。

登录按钮只根据服务端已启用的站点配置展示。客户端密钥、端点等认证配置在点击登录时校验，
不会因为密钥解密失败而隐藏入口。点击后提示暂时不可用时，请检查服务端日志中的站点初始化失败原因，
并核对客户端配置及数据目录中的加密密钥文件。

### 9.2 单点登录回调失败

检查身份服务登记的回调 URL 是否与 DocHub 显示的地址完全一致，包括协议、域名、端口、站点 ID 和路径。

错误提示为先登录门户时，应先登录身份服务门户，再返回 DocHub 重新发起登录。

### 9.3 修改组织成员后权限未更新

确认用户登录的是正确账号，并检查：

- 用户是否已保存到目标组织。
- 项目或文档是否授权给该组织。
- 用户是否仍有其他个人授权或组织授权。

组织成员变化和授权变化会立即参与下一次权限判断。

### 9.4 用户能看到项目但只能打开部分文档

这通常表示用户只有文档级授权，没有项目级授权。此时目录树、搜索和默认文档只展示已授权内容，属于预期行为。

如需读取整个项目，应增加项目级用户授权或组织授权。

### 9.5 无法修改自己的角色

系统禁止管理员直接降低自己的角色，避免误操作导致当前会话失去后台能力。应使用另一名管理员账号完成角色调整。

### 9.6 无法删除最后一名管理员

系统要求至少保留一个管理员。先将另一名成员提升为管理员，再调整原管理员角色。

### 9.7 分支同步失败

检查：

- 分支名称是否真实存在。
- SSH 仓库地址是否正确。
- DocHub 服务端 SSH 凭据是否有只读权限。
- Git 主机是否在允许访问范围内。
- 网络和证书配置是否正常。

同步失败期间，上一份成功快照仍可供有权限的用户阅读。
